# Bioblitz Report

Drop in your bioblitz's iNaturalist sightings export and get a tidy, printable nature report for the landowner: the numbers, your notable finds, and the full species list.

Live: https://bioblitz-report.vercel.app

## What it does

- **Reads the iNaturalist export in your browser.** Add the `.zip` iNaturalist gives you, or the `.csv` inside it. The file is never uploaded anywhere.
- **Shows you which columns to tick** on iNaturalist's export page, and tells you what the report loses (and how to export again) when helpful columns are missing.
- **Counts species properly.** Subspecies and varieties count once, under their species. Sightings identified only to a broader group (like "Bumble Bees, genus *Bombus*") are listed separately and aren't counted as extra species. Sightings with no identification yet are counted as sightings only.
- **The numbers:** species, sightings and groups, plus a table of species and sightings per group (birds, mammals, insects, plants, fungi and lichens, and so on).
- **Notable finds you choose.** The app can't know what's special on that land, so you tick the species to feature and add a short note to each.
- **Plain statement** at the top: the report lists what volunteers saw, and is not a professional survey.
- **Print-friendly.** Title, landowner, place, date (filled in from the sightings) and organizer are editable. The printed page has the numbers, the notable finds, then the full list sorted by group and family with common and scientific names. Print it, or choose "Save as PDF" in the print window.
- **Which sightings count:** confirmed and not-yet-confirmed sightings (the default, leaving out iNaturalist's "casual" ones: planted, captive, or missing a photo or date), research grade only, or everything. Species with no confirmed sighting are marked with an asterisk.
- **Protects sensitive species.** By default it leaves out every sighting whose location iNaturalist hides (`geoprivacy` or `taxon_geoprivacy` of obscured or private, or `coordinates_obscured`), and every sighting of a species iNaturalist treats as sensitive, even one that slipped through unhidden. The report says how many were left out. The organizer can include them with a clear warning. If the file has none of those columns, the app warns before you share.
- **Never shows people or places from the file.** Observer names, usernames, coordinates, place names and descriptions are never read into the report.
- **Try it first** with a sample file of made-up sightings (`public/sample-observations.csv`, synthetic: no real observations or users).

Works from 375px wide, follows your system's light or dark mode (the printout is always black on white), has visible keyboard focus, and respects "reduce motion". No account, no cookies, no analytics scripts, no third-party scripts, and no tracking by the app. Like any website's host, Vercel keeps request logs that can include IP addresses and referring sites. We only look at weekly totals of requests to load the app, grouped by referring site, to see whether people find it. We don't look at individual requests.

## The iNaturalist columns

Column names are taken from iNaturalist's own export code (`Observation::BASIC_COLUMNS`, `GEO_COLUMNS`, `TAXON_COLUMNS` and `EXTRA_TAXON_COLUMNS` in [inaturalist/inaturalist](https://github.com/inaturalist/inaturalist/blob/main/app/models/observation.rb)); the export page labels each checkbox with exactly these names. The "Taxon Extras" columns start unticked, so organizers need to tick two of them.

| Column | Section on the export page | Used for |
| --- | --- | --- |
| `scientific_name` | Taxon (ticked by default) | the name each sighting was identified as (required) |
| `common_name` | Taxon | common names |
| `iconic_taxon_name` | Taxon | the group: birds, plants, fungi, ... |
| `quality_grade` | Basic | research / needs_id / casual |
| `observed_on` | Basic | filling in the date |
| `geoprivacy`, `taxon_geoprivacy`, `coordinates_obscured` | Geo | leaving hidden sightings out |
| `taxon_family_name` | Taxon Extras (tick it) | sorting by family |
| `taxon_species_name` | Taxon Extras (tick it) | folding subspecies into their species |

Without `taxon_species_name` the species is worked out from the first two words of the scientific name. Without `iconic_taxon_name` the group is worked out from `taxon_kingdom_name`, `taxon_phylum_name` and `taxon_class_name` if those were exported. Everything else in the file is ignored.

## Develop

Needs Node 22+ and pnpm.

```sh
pnpm install
pnpm dev       # local dev server
pnpm test      # unit tests (vitest)
pnpm check     # typecheck + tests
pnpm build     # production build into dist/
```

- `src/logic/csv.ts`: a small CSV reader (quoted fields, commas and line breaks inside quotes, doubled quotes, BOM, any line ending, short rows).
- `src/logic/zip.ts`: opens iNaturalist's export zip with the browser's built-in `DecompressionStream`, no library.
- `src/logic/report.ts`: species counting, broad identifications, quality and sensitive-sighting filters, sorting by group, family and name.
- `src/logic/groups.ts`: iNaturalist's iconic taxa with plain names, in report order.
- `src/render.ts`: builds the report. All text from the file goes in as text, never as HTML.
- `src/main.ts`: the page.

Tests cover CSV parsing, zip reading, species counting and grouping, sensitive filtering, sorting, and the rendered report (it checks that no username, name, coordinate, place or description from the sample appears, even with sensitive sightings included).

It is a static site (Vite + vanilla TypeScript) with no environment variables, secrets, backend or runtime dependencies. It's deployed on Vercel's free tier.

## Maintenance

This app is looked after, not left behind. Dependabot proposes dependency updates. The Somebody Build This steward checks on the app each month and reviews security alerts in a weekly security check. Updates go through review and automated checks before they are merged.

Found a problem, or an export it reads wrongly? [Open an issue](https://github.com/TeeKraken/bioblitz-report/issues) on this repository and describe what happened (please don't attach real exports with people's names or locations).
